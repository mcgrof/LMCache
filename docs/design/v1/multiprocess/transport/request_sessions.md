# Request session identity

Status: proposed. The request transports do not yet expose a handler-local
client-session identity. KMesh multiprocess admission remains closed.

KMesh registration must bind a worker to the request client that actually
registered its cache. A session identifier supplied inside an ordinary request
payload is insufficient: a scheduler could echo evidence from another worker.
The server therefore needs transport-derived context available while a handler
runs, including on normal and client-affinity worker pools.

The proposed context contains a digest of the transport name and its logical
client identity. For ZeroMQ this identity is the routing frame received by the
server. For gRPC it is the existing per-client binary metadata generated by
`GrpcMultiprocessClient`. Neither a server URL nor a peer address is an identity
fallback. This is cooperative same-user ownership, not authentication. A client
that deliberately reuses another client's identity is outside the threat model.

The identity names a client instance, not an individual TCP connection. A fresh
client instance gets a new identity. Automatic transport reconnection by the
same client retains its identity; a missed KMesh heartbeat nevertheless revokes
its registration irreversibly. Rebinding requires a fresh rank barrier.

Each request binds its context for the handler's dynamic extent and resets it
on return or exception. Worker-pool dispatch must copy that request context into
the actual executor thread. Completion callbacks retain accepted ownership
tickets explicitly; they must not infer the submitting client from a later
thread-local context.

Legacy gRPC callers may omit the metadata and ordinary handlers must continue
to work. Missing, malformed or duplicate identity metadata leaves the request
without a session. A handler requiring ownership must then refuse before any
work is accepted. It must not substitute a URL, peer name or scheduler value.

Validation must cover isolation across requests, nested contexts, exceptions
and executor threads. Loopback transport tests must exercise synchronous,
normal-pool and affinity-pool handlers for each transport, distinguish separate
clients and demonstrate that legacy calls receive no invented identity.
